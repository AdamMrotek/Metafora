The agent studio

Author one interview, and the tests it has to pass are written with it.

An intake agent is not a prompt. It is a script, a safety break, two escalation routes, a table of what it may call and from where, and the guidance for the report a clinician signs. Every one of those is a thing that can be tested — so this screen authors them in one place and compiles the suite out of them. Nothing here is written twice.

Six blocks one published version Every block compiles to a test Published versions are frozen
Design language: unchanged. Same tokens as the clinician and patient portals, and the same rule that anything coloured means something. What is new is what red means here: on this surface it is never a patient, it is a version that will not ship. The three screens share one token file on purpose — see ux-clinical-dashboard.html and ux-patient-portal.html.

How it works

Six blocks, and the version they publish into

They are listed in the order the conversation meets them: the script runs, the break sits under every turn of it, the two escalation routes decide who is woken and how fast, the tools are what the agent may reach for, and the report guidance is the last thing to run — the sentence a clinician actually reads.

A block is not a section of a prompt. Four of the six never enter the prompt at all: the break is a gate that runs before generation, the routes are policy, the tool table is a permission matrix enforced in-process. Writing them as prose in a system message is exactly how they stop being enforceable.

BLOCK I Interview script Sections, questions, the field each one captures, and how hard to push for it. The only block the patient hears in full. → capture + scenario cases
BLOCK II Safety break The catalog of things that end the conversation. Runs on the committed turn, before any generation — so the model is not in the loop by construction. → fixture per entry + gate order
BLOCK III Urgent escalation Who is woken, how fast, and what happens when nobody answers. A rota with a timeout, never a person. → routing + timeout cases
BLOCK IV Soft review escalation Owed, but not timed. The interview finishes, lands at the top of the queue, and nobody's phone rings at 02:00. → priority + no-page cases
BLOCK V Tools What it may call, from which states, with which arguments and how many attempts. A matrix, not a list. → correctness + reachability
BLOCK VI Report guidance The shape of the summary, the rules about quoting, and the things it must say it did not ask. → rubric-judged cases
OUTPUT A published version One immutable ProtocolVersion: prompt blocks, red-flag set, tool states, report schema — and the suite that passed on the way out. Every interview pins one, so a report that says “severity 7” can always be read back against the question that was asked. frozen at publish · never edited in place

Six things to write, one thing to ship. The card on the right is the only one filled, because it is the only one a patient ever meets.

The studio

You author the left, and the right compiles

It answers three questions, in this order:

  • What will this agent say?
  • What will it never do?
  • How would I know it works?

The third one is the reason for the third column. It is not a preview and not a summary — it is the product of the other two, on screen permanently. The moment tests are a separate task from authoring, they get written last, written thin, and written by whoever lost the argument.

Goal: you cannot add a red flag without adding the utterance that proves it fires, because the field that takes the utterance is the field that generates the fixture.

The four safety blocks

Four outcomes, and only one of them stops the conversation

These are not four intensities of one setting, and the studio must not let them look like it. One ends the interview with no model in the loop. One starts a clock against a rota. One joins the queue at the top and rings nobody. One never fires at all — it shapes the sentence a clinician reads at the end.

Spending red on all four is how a clinician learns to ignore red. So the ladder is authored as four separate blocks, each with its own routing, and the studio paints them the way the clinician portal will paint them.

Block II · safety break Ends the conversation Runs on the committed patient turn, before any generation is released. The reply is a pre-rendered line — fixed text, synthesized at build time — so the most safety-critical path in the product involves no model call and no vendor round trip. The interview terminates in alert and an urgent escalation is raised with it. no LLM in the path ~400 ms to speech
Block III · urgent escalation Starts a clock Notifies the on-call rota immediately, then the assigned clinician. It has its own lifecycle — raised, notified, acknowledged, closed — and it must be closed by a human even if the interview is never read. Unanswered inside the timeout, it moves to the next rota target. urgent review06:41 timeout 15 min → next target
Block IV · soft review escalation Owed, but not timed The conversation carries on to the end. The interview lands in the review queue at the top, with the trigger quoted on the row, and nobody is paged. This is the block for the things that are worth a clinician's eye tomorrow morning and are not worth a phone call tonight. priority · high no page, no clock
Block VI · report guidance Shapes what is read Never fires, never routes. It decides the fields, the order, what must be quoted verbatim, and — the rule most often missed — what the report must say it did not establish. A summary that omits its own gaps is worse than a short one. 6 fields rubric-judged, not string-matched

The safety break, up close

Every entry carries the sentence that must trip it

The utterance column is not documentation. It is the fixture: on every commit, the suite replays each one through the gate and asserts that the interview ends in alert, that the pre-rendered line was spoken, and that the model was invoked exactly zero times. A row without an utterance cannot be published, which is why the block's dot is amber in the rail above.

Detected by is the double-detection column. A phrase scan is instant and literal; a model rubric catches the same clinical fact said in words nobody listed. Rows that matter most carry both, and the two are ORed — never ANDed, because an AND means one detector's miss silences the other.

Tools

What it may call, and from where

A list of tools tells you what exists. A matrix tells you what is reachable, and reachability is the property that has actually caused harm: a verification tool callable from a closed state is three fabricated attempts and a patient locked out of their own intake.

So the three closed states are shaded as a block. Nothing is callable from them, and that is one structural rule checked on every commit — not five separate decisions someone remembered to make. Each tool row also carries its own argument schema and attempt cap, and both generate cases: the model must not fabricate an argument it was never given, and must not fire a tool in response to “Yes, that's fine.”

Report guidance

The last block is the one a clinician actually reads

Everything above decides what happens during the call. This decides what survives it. The report guidance block sets the fields and their order — which is the order the review composer renders them in — plus a small number of rules that are enforced by rubric rather than by string match.

Three rules earn their place. Quote, don't paraphrase, for anything that drove a flag: “breathless walking upstairs, that's new this month” is evidence, and a tidy summary of it is not. Never name a diagnosis, because the assistant is taking a history, not making one, and a clinician reading a suggested diagnosis is anchored before they have read the transcript. Say what was not established, because a summary that hides its own gaps is more dangerous than a short one.

Versions

A draft is editable, a published version never is

A report says “severity: 7”. That means nothing six months later unless you can recover the question that was asked and the red-flag set that was armed at the time. So publishing freezes: prompt blocks, red flags, tool states, report schema, model configuration, and the suite result that let it out. Editing means forking a draft from it.

This also gives the escalation-rate metric on the clinician dashboard a dimension worth grouping by. A rate that moves on the day a version ships is a different fact from one that drifts.

The handover

Every block leaves the studio as something executable

Nothing authored here ends up as advice. The script becomes a state machine, the break becomes a gate that runs before generation, the routes become an escalation record with its own lifecycle, the tool table becomes a permission check in-process, and the report guidance becomes the schema the review composer renders. The suite is what proves each of those translations survived.

The seam: the studio publishes a version, the evals runner proves it, and the clinician portal deploys it to a patient. Three screens, one artefact travelling between them.
